# Документация

Единая точка входа. Статус документа определяется каталогом, чтобы текущее
поведение не смешивалось с планами и историей.

## Текущая версия: 0.3.1

Документы в [`current/`](current/) описывают текущий код:

- [Архитектура](current/architecture.md) — command-only API, PTY, lifecycle,
  cursor-чтение, секреты, ошибки и audit.
- [Эксплуатация](current/operations.md) — установка, OpenCode, SSH/Telnet/Serial,
  нестабильные соединения, типовые ошибки и завершение сессий.
- [Модель безопасности](current/security.md) — локальная модель доверия, секреты
  и честные границы возможностей.
- [Тестирование](current/testing.md) — unit, PTY integration и stdio-проверки.
- [Результаты проверок](current/validation.md) — что подтверждено, а что ещё
  требует живого оборудования.

## Планы

[`plans/`](plans/) содержит только незавершённые необязательные направления.

- [Backlog](plans/backlog.md) — hardware-проверки, наблюдаемость и возможные
  ограничители после реальной эксплуатации.

## История

[`history/`](history/) — историческая справка, не руководство для работы.

- [ТЗ и план 0.2.0](history/0.2.0-plan.md) — утверждённое ТЗ переработки,
  реализованное в 0.2.0.
- [Этап 9 / 0.1.x](history/0.1.x.md) — переход к raw terminal API.
- [Документация 0.1.x](history/0.1.x/) — прежняя structured-модель, Paramiko,
  policy и host-key store.
- [Этапы 0–8](history/0-8.md) — command gateway и nested-маршруты.

## Правила поддержки

1. Изменения кода синхронно отражаются в `current/`.
2. Новое целевое поведение сначала фиксируется в `plans/` и не выдаётся за
   работающее.
3. После релиза план переносится в `history/`, а `current/` описывает только
   фактическое поведение.
4. Одно описание — один authoritative документ. README даёт обзор, детали
   находятся в `current/`.
5. Реальные адреса, hostnames, usernames, fingerprints, секреты и production
   transcripts в репозиторий не добавляются. Примеры используют
   `192.0.2.0/24` и `example.net`.
