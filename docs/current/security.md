# Модель безопасности 0.3.0

## Границы доверия

Сервер — доверенный локальный компонент с правами пользователя, а не sandbox.
Он запускается MCP-клиентом через `stdio` и предоставляет persistent terminal.

SSH и Telnet запускаются как настоящие системные клиенты. Аргументы SSH не
фильтруются, поэтому OpenSSH options вроде `ProxyCommand` могут запускать
локальные команды. Это осознанная модель «сначала функциональность»: сервер не
заявляет, что разрешает только сетевые подключения.

Проверка host key выполняется OpenSSH по правилам пользователя. Собственного
`known_hosts`, host-key store и политик `strict`/`accept_new` больше нет.

## Permissions

Обязательного permission popup для `open_session` нет. Клиент может добавить
собственные правила, но установка MCP от них не зависит. Внутри уже открытой
сессии отдельного подтверждения на каждый ввод нет.

Это не средство защиты от вредоносной модели или скомпрометированного клиента.
Изоляция, allowlist команд и фильтрация SSH-опций в 0.3.0 не реализованы.

## Секреты

- `terminal_write_secret` принимает ровно один источник: `value`, `env` или
  `file`.
- Значение записывается в поток, добавляется в redactor сессии и не возвращается
  в результате.
- В audit попадают только тип источника и число байт.
- `value` остаётся в аргументах вызова, контексте модели и истории клиента. Это
  явно документированный компромисс; `env` и `file` предпочтительнее.
- Пароль, переданный через обычный `terminal_write` или включённый в `command`,
  может остаться в истории клиента и audit. Сервер не может это гарантировать.
- Redaction работает только для секретов, уже зарегистрированных в сессии.
  Вывод, полученный до регистрации секрета, не переписывается задним числом.

## Аудит

JSONL-аудит обязателен и работает fail-closed: если запись о начале действия
невозможна, действие не выполняется. Каталог создаётся с `0700`, файл — с
`0600`.

Записываются команда открытия, redacted-ввод, offsets чтения, состояния,
exit code и ошибки. Значения секретов не записываются. Аудит не является
permission gate и не фильтрует команды.

Путь по умолчанию:

```text
$XDG_STATE_HOME/network-terminal-mcp/audit.jsonl
~/.local/state/network-terminal-mcp/audit.jsonl
```

## Сетевая безопасность

- Telnet передаёт данные и пароли открытым текстом; используйте его только там,
  где это принято оператором.
- Serial — локальное физическое подключение; права определяются ОС.
- Для production предпочтительна отдельная AAA-учётная запись и TACACS/RADIUS
  command authorization. MCP не обходит и не заменяет их.
- Изменения конфигурации остаются обычным вводом. Ответственность за rollback
  (`commit confirmed`, `reload in`, `schedule reboot delay`) лежит на модели и
  операторе, а не на серверном фильтре.

## Что не является гарантией

Сервер не защищает от:

- вредоносных команд, введённых моделью или пользователем;
- опасных SSH-опций и локального выполнения команд;
- потери секрета, уже попавшего в контекст клиента;
- сетевого перехвата Telnet-трафика;
- ошибок на оборудовании и последствий конфигурационных изменений.

Ограничители добавляются только после документированной эксплуатационной
потребности и не должны усложнять базовый терминал.
