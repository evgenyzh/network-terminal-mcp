# Backlog после 0.2.0

Это необязательные направления, а не скрытые требования к выпущенному 0.2.0.
Они не должны усложнять базовый command-only терминал. Ограничители добавляются
только после подтверждённой эксплуатационной потребности.

## Hardware и транспорты

- Собрать обезличенные transcripts для BDCOM, EcoSGE, Eltex и PON-платформ,
  если появится доступ к таким устройствам.
- Проверить Telnet и TCP console на реальном оборудовании, включая terminal
  servers с menu/banner до shell.
- Проверить Serial на реальном кабеле: login, boot output, control keys и
  отключение устройства.
- Оценить Windows PTY только при появлении реального пользователя этой
  платформы.

## Работа с изменениями

- Вести рекомендации по rollback для конкретных CLI (`commit confirmed`,
  `commit trial`, `reload in`) в модельной инструкции, не превращая их в
  серверный command filter.
- Решить по фактическому опыту, нужны ли отдельные подтверждения для
  destructive-команд на стороне клиента. Серверный allowlist не возвращать.

## Наблюдаемость и ресурсы

- Определить по реальному использованию срок хранения audit и необходимость
  ротации.
- Добавить опциональные transcripts только если audit окажется недостаточным
  для воспроизведения проблем.
- Пересмотреть лимит одновременных сессий только при подтверждённой нехватке
  ресурсов или необходимости группового опроса.
